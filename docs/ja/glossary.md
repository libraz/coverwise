# 用語集

coverwise での用法をまとめ、その語が API のどのフィールドや関数に現れるかを各項目に添えています。組み合わせテストで複数の意味を持つ語については、coverwise が実装しているほうの意味を示します。

## モデル

**パラメータ** — テスト対象システムの変動要素で、値の有限リストを持ちます。`parameters` で宣言します。`estimateModel` は `stats.parameters` にパラメータごとの項目を返します。

**高カーディナリティのパラメータ** — 値を多く持つパラメータ。ベンチマークの表では、そうしたパラメータ少数からなるモデルを `high-card` と略記します。`5 × 20 high-card` の行は値を 20 個持つパラメータが 5 個という形状で、モデルが小さくても必要タプル集合が大きくなります。

**値** — パラメータが取る離散的な選択肢の 1 つ。文字列・数値・真偽値をそのまま書くか、`invalid`・`aliases`・`class` を併せ持つオブジェクトとして書きます。値の比較では ASCII の大小文字を畳み込むため、大小文字だけが異なる 2 つの値を同じパラメータに持たせることはできません。

**エイリアス** — 値に対して解決時に受け付ける別の綴り。値オブジェクトの `aliases` で宣言します。出力に現れるのは常に宣言した綴りで、エイリアスではありません。

**無効値** — `invalid: true` を付けた値。正常系の行には現れず、正常系のカバレッジにも数えません。異常系テストの素材になります。

**等価クラス** — システム内で同じ経路を通ると期待される値をまとめるラベル。値オブジェクトの `class` で宣言します。

**境界値** — 数値範囲の端、およびその隣にある値。`type` と `range` を持つパラメータは、各端の外側 1 つ・端そのもの・内側 1 つの計 6 つに展開されます。

**サブモデル** — 独自の強度を与えたパラメータのグループ。モデル全体より深く網羅したい部分に使います。`subModels` で宣言します。

**重み** — 同じ数の不足を埋められる値どうしの優先度。`weights` で宣言します。重みが大きい値は選ばれやすくなりますが確定ではなく、スイートが完全網羅に達するかどうかは変わりません。

**シードテスト** — 生成結果に必ず含める行。`seeds` で宣言します。ジェネレータはシード行を順序どおり保持し、残りの不足をその周りで埋めます。

**制約** — 生成される各行が満たすべき、パラメータ値についてのブール式。`constraints` で宣言します。構文は[制約構文](constraints.md)にあります。

**テスト数の上限** — 1 回の実行が生成してよい行数の上限で、`maxTests` で宣言します。0 は無制限です。

## カバレッジ

**テストケース** — すべてのパラメータに値を 1 つずつ割り当てた完全な組み合わせ。`result.tests` の 1 行です。

**カバリング配列** — 必要なタプルがすべて少なくとも 1 回現れるテストケースの集合。`generate` が返すものです。

**タプル** — 異なる t 個のパラメータから取った値の組み合わせ。`(os=Windows, browser=Chrome)` などです。カバレッジは行数ではなくタプル単位で数えます。

**カバレッジ単位** — 同じものをカバレッジの側から呼んだ名前で、スイートが含むべきタプル 1 つを指します。`result.stats.totalTuples` がその個数です。

**強度（t）** — 1 つのカバレッジ単位が値を取るパラメータの個数。`strength` で宣言し、2 がペアワイズで既定値です。`subModels[].strength` はグループ単位で上書きします。強度はカバレッジ単位の性質であり、テストケースの性質ではありません。テストケースは常に全パラメータに値を割り当てます。

**必要タプル集合** — スイートが含むべきカバレッジ単位の集合です。モデルの全 t-タプルから、無効値を含むものと、制約を満たすどんな行も持ちえないものを除いたものになります。`result.stats.totalTuples` がその大きさで、制約がこれをどう縮めるかは[制約と必要タプル集合](primer/constraints-and-the-universe.md)で追っています。

**カバレッジ率** — 網羅済み単位を必要単位で割った 0 から 1 の値。生成後は `result.coverage`、解析後は `report.coverageRatio` です。必要タプル集合が空の場合は完全網羅として報告されます。

**未網羅タプル** — スイートのどの行も持たない必要単位。`result.uncovered` と `report.uncovered` が読みやすい `display` 文字列付きで列挙します。総数は `uncoveredCount`、そのうち一覧から省かれた数は `omittedUncovered` です。

**無効なテスト行** — 解析対象のスイートに含まれる行のうち、パラメータモデルが説明できないもの。パラメータが欠けているか、モデルが宣言していない値を指しています。`report.invalidTests` が理由付きで挙げ、これらの行はカバレッジ計算から外れます。

**異常系テスト** — 無効値をちょうど 1 つだけ含む行。拒否された原因をその値 1 つに帰せます。`result.tests` とは別に `result.negativeTests` が保持します。

**異常系カバレッジ** — 無効値を 1 つ含むタプルに対する同じ計算。`result.negativeCoverage` です。

**クラスカバレッジ** — 値ではなく等価クラスの水準で行う同じ計算。`result.classCoverage` で、いずれかの値が `class` を宣言しているときに現れます。

## 生成

**generate** — モデルからカバリング配列を構築します。

**analyze** — 既存のスイートをモデルに照らして測定します。必要タプル集合はジェネレータとは無関係に列挙されます。`analyzeCoverage` です。

**extend** — 既存のスイートをそのまま結果の先頭に残し、不足を埋める行だけを追加します。`extendTests` です。

**モデル推定** — スイートを作らずにモデルの規模を測ることです。`estimateModel` が `totalTuples` と `estimatedTests` を返します。後者はどちらの向きにも上限・下限ではありません。

**貪欲法** — coverwise が使うアルゴリズム。各行を、まだ開いているカバレッジ単位を最も多く閉じられるように選びます。真の最小解を探索せずに、実用上ほぼ最適なスイートが得られます。

**制約枝刈り** — 行を組み立てる途中の部分割当に対して制約を評価し、違反する行をそもそも作らないようにすることです。生成してから捨てるのではありません。

**RNG シード** — ジェネレータの乱択をすべて固定する数値。`seed` で宣言し、既定値は 0 です。

**決定性** — 同じ妥当なモデルと同じシードから同じスイートが得られる性質。どこまでが保証でどこからが違うかは[決定性](determinism.md)にあります。
